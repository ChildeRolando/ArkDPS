# ArkDPS · 明日方舟局内 DPS 统计器

底层数据可行性已按确认的 V1 范围通过，项目处于正式产品开发。当前实时 GUI 使用统一统计结果，支持伤害、治疗、有效护盾、多面板独立配置、头像悬停和固定详情；HUD 窗口已接入同一结果。历史页可浏览最近 100 局并保存统计 PNG、导出原始 JSON。连接设置、系统托盘、窗口布局恢复与事件观测开关已接入；当前候选已改为 C#/WPF 展示与独立 Python 采集子进程，并提供同包运行时构建；实机端到端发布验收仍未完成。详见 [GUI/HUD 面板契约与复现命令](docs/panel-model.md)。

已确认的产品规则集中在 [V1 设计基线](docs/v1-design.md)，包含 GUI/HUD、多面板、统计口径、历史与启动恢复；技术能力缺口单独列明。

实测依据见 [底层能力报告](docs/capability-validation.md)及[补充实验](docs/recovery-validation.md)，覆盖已测数值盾、召唤伤害/治疗/护盾归属及实时事件。最新产品决定不做独立重连恢复需求：中途启动读取已有伤害/治疗累计，DPS/HPS 从可靠采集时起算。此前护盾累计无法补读已记入 [开发备忘](docs/development-notes.md)，不阻塞开发。研究证据不等于所有机制均已通过产品验收；以下限制仍适用。

产品 UI 只有 C#/WPF（`desktop/ArkDPS.Desktop`）。旧 Tk 面板已归档封存到 `archive/legacy-tk`，不再支持、不得运行，其截图/回执与 ARK-14 旧结论都不能作为当前验收证据；UI 验收统一走 `acceptance/verify_wpf.py`。

## Windows 分发

`1.0.0-rc.1` 以 WPF 便携 ZIP 分发：解压到用户可写目录，运行 `ArkDPS.Desktop.exe`，包内自带 .NET 与 Python 3.12.10，不需要系统 Python。构建用 `python tools/package_windows.py`，验收用 `acceptance/verify_wpf.py` 与 `acceptance/verify_wpf_package.py`。初版仅以 MuMu 12 / Android 2.7.91 为兼容目标；未获得对外发布授权。构建、许可与验收矩阵详见[发布说明](docs/windows-release.md) 和 [变更日志](CHANGELOG.md)。`start.cmd` 是**源码运行**入口，不是便携版安装步骤。

双击 `start.cmd`，打开原生实时统计 GUI。首次仅创建伤害/本局总量/近 5 秒 DPS 面板，不自动打开 HUD。适配本机 MuMu 12、官方安卓客户端 **2.7.91**，需要模拟器 Root 已开启；当前桌面为 C# / .NET 10 / WPF，Python 只负责后台采集与统计。源码首次构建需 .NET 10 SDK；可分发包自带 .NET、Python 3.12.10 和可选 Frida 客户端，不依赖用户机器的 Python。见 [桌面运行时与同包分发](docs/desktop-runtime.md)。

左侧导航栏可即时切换六套原生皮肤：孤星、危机合约、巴别塔、长夜临光、叙拉古人、原始界面；覆盖历史、设置、HUD 和统计 PNG。重启恢复选择，旧配置自动迁移；切换不重建战斗、面板或 HUD。历史支持关键词搜索及结果/模式筛选，筛选隐藏的所选战绩仍保留，HUD 继续跟随实时新局。

新建或复制面板后可独立选择类别、排行和速率；伤害总量面板在类型图例右侧提供「仅显示有效伤害」开关；宽窗并列，窄窗堆叠滚动。头像悬停显示姓名，数值悬停显示最多 1 位小数的原值（未舍入值只在 JSON 导出中保留），点击头像/行固定详情；右侧明细的数值取整、零值行隐藏，并分开展示有效伤害与过量伤害；「被减伤率」已经预留独立槽位，未采集公式前伤害时显示“—”，不猜测、不补零。鼠标悬停列表时暂停重排，数值继续更新。离场头像灰显，未知不写零。“打开到 HUD”创建置顶紧凑窗口；从源面板锁定/解锁和调透明度，拖动 HUD 顶栏移动，拖动右下角调整大小。HUD 的类别、排行和速率由源面板控制。

主窗**连接设置**可切换自动检测、ADB 路径、实例地址和多实例目标，并开关事件观测；设置页区分关闭、依赖/端点缺失、运行中断和不支持的游戏版本，降级时明确提示仅伤害/治疗快照继续。配置写入 `runtime/connection.json` 与 `runtime/layout.json`，详情见 [设置、托盘与窗口配置恢复](docs/settings-and-layout.md)。

关闭 GUI 会隐藏到系统托盘，已打开的 HUD 与采集继续运行；托盘双击或“打开主窗口”恢复 GUI，只有“退出 ArkDPS”才停止采集并清理本工具创建的观察器、会话与 ADB 转发。重启恢复面板配置、HUD 位置/尺寸/透明度/锁定和 GUI 几何；显示器移除或 DPI 变化后窗口回到可达位置。损坏的布局文件会先备份再使用默认布局。

所有实时面板共享 `BattleRuntime` 的一份统计结果；顶部区分连接、事件降级、暂停、过期与已结束记录。首次连接优先读取已验证游戏构建的类型槽。大厅里尚未解析的类型槽可从已加载的类定义表定位，元数据不可用或校验失败时回退到设备端批量定位。**重新定位**可重建连接。**历史战绩**无需连接游戏即可打开本地归档；选择演习、失败、退出或未知结果记录，独立切换类别、排行和速率。浏览、刷新或离开历史页都不会改变实时源面板和采集；新局归档后点击**刷新列表**，当前查看的局保持不变。

历史窗口的**保存统计截图**生成包含所选战绩、口径、覆盖说明和全部排行行的 PNG，不受窗口尺寸或滚动位置限制。**导出 JSON**保存同一版本化 `BattleRecord` 的未舍入数值、未知 `null`、可靠零、归属、口径及覆盖起止。保存可取消；同名文件需确认，写入失败保留旧文件，禁止将导出保存到采集器管理的历史目录。小窗口或大字体可**收起列表**，统计面板和详情另有外层滚动条。

## 统计口径

- 总伤害：客户端每个干员统计条目中的物理、法术、真实、元素伤害累计之和，**包含过量伤害**；治疗不计入。名称不认识时保留原始 ID。地图固定 NPC、已经死亡或撤退干员的本局历史输出继续保留。
- 元素爆条伤害：按目标实例归给最后一次元素损伤来源，并折入有效伤害/过量伤害，不在明细中单列；找不到最后来源时不猜测，保持未知。
- 过量伤害：独立的事件派生指标。仅当一次伤害使目标实际 HP 归零时，以该次原生来伤值减去同帧已观测的护盾/抵挡吸收，再减去实际扣血；原生结算值是吸收前的来伤（捕获样本 `m_value` 14、`realDelta` 0、HP 未变），吸收量必须单独排除，不得计为过量。事件覆盖不完整、目标未知、吸收上下文未验证或扣血证据不足时显示 `—`；不补零，也不改变总伤害、排行、柱长、占比和 DPS。未验证护盾或非玩家来源只影响对应护盾/来源的过量，不再关闭其他干员的伤害、接敌与过量事件。已知时按原生伤害类型分组；总量排行的每条属性伤害段末端用半透明斜纹和警戒线标出其中的过量部分，近 5 秒排行不派生过量。中途启动时过量只覆盖事件观察区间，`overkill_coverage_start` 标出起点，不补算观察前过量。合成事件已覆盖普通命中、击杀、研究样本、护盾吸收与覆盖缺失；实机逐干员对账待事件观测（ARK-21）恢复后补验。
- 全局 DPS：该条目总伤害 ÷ 本局游戏逻辑时间，包含部署前和未攻击的时间。不是在场 DPS，也不是技能 DPS。
- 近 5 秒 DPS：现在由统计核心计算，观察不足 5 秒使用实际已观察游戏时长，满 5 秒后滚动；缺口或无法建立可靠窗口时显示 `—`。
- 暂停不消耗游戏时间，因此暂停时 DPS 保持在暂停瞬间的值。1×/2× 不会直接乘进伤害率。
- 窗口使用累计适配器的可靠宿主归并与在场映射；未知来源不猜测，已有可靠累计保留。覆盖边界见[累计适配器](docs/snapshot-adapter.md)，不能外推到全部召唤物、分身或特殊机制。

**总伤害不是有效扣血量。** 夜刀末击实测：敌人剩余约 44 HP，干员累计增加 200，敌人 HP 降至 0，全局字段增加 44。此例证实干员计数包含过量伤害，全局字段在此例中按实际扣血增长；不能据此断言所有特殊机制的结算方式。同一样本的结算伤害 200、实际扣血 44，独立展示为过量 156；另一研究样本公式伤害 771.5、实际扣血 185.5，过量 586。窗口合计使用逐干员总和；导出同时保留 `global_total` 和 `global_difference`，不混用两种口径。此前 NPC 与全局字段的所有差额尚未逐一归因。

## 底层 Demo 验收：通过（限定范围）

- 在用户本机的演习战斗读取真实数据，逻辑时间从约 26.60 秒推进到 40.37 秒，捕获 1× 与 2×，之后再次暂停。
- 普罗旺斯 4,747.40625；天火 3,272；史尔特尔从 1,660 增至 3,320；新增冻河 1,276。
- 每个已发布样本通过设备侧逻辑帧前后相等校验；暂停样本稳定。动态完整捕获保存在 `runtime/captures/`，报告在 `VALIDATION.json`。
- 隔离夜刀的五次普攻：累计增量 280、280、200、200、200；前四次与敌人扣血一致，末击按上述过量伤害口径一致。伤害与 HP 两组读取都通过帧校验，且仅接收两者同帧记录。
- 撤退再部署：日志确认 SPAWN → WITHDRAW → SPAWN；夜刀总伤害由 1,160 增至 2,560，只有一个统计条目。此段因审计脚本遇到敌人列表瞬态变化而提前停止，未完整记录重部署后的逐次 HP 对账；保留缺口，不宣称逐击验证。
- 实机重开同一演习：新局 0.80 游戏秒，未部署夜刀；旧局 2,560 未带入，仅有固定 NPC 普罗旺斯 373。此前误判为旧局的普罗旺斯、天火是本地图 NPC 的有效历史数据。
- 强化战局识别：同时核对原生对象回指、Logger 所属对象；多个候选同时有效则拒绝猜测。每个完整采样前后核对对象链；会话身份包含进程、战斗、统计及关卡对象，避免仅凭可复用地址判断换局。
- 22 项测试通过，覆盖暂停、倍速口径、观察不足、换局/回退/累计重置、新干员、治疗排除、非法数值、延迟队列、强制重新定位、旧归属拒绝和候选歧义。更新后的窗口已实机重新采到新局的 373。

验收范围是本机版本上的直接伤害读取、游戏时间 DPS、撤退累计和单次同图重开清空。近 5 秒 DPS 为估算；召唤物、持续伤害、复杂技能、元素归属、任意地图切换、重启游戏和菜单自动恢复仍需正式产品阶段验证。导出保存框尚未完成端到端验收。

原始证据和可重放校验在 `acceptance/`。运行 `python acceptance/verify_evidence.py` 可重新核对五次命中、撤退记录、换局清空和倍速采样；机器可读结论见 `VALIDATION.json` 与 `acceptance/evidence-summary.json`。审计脚本的瞬态错误已改为拒绝该样本并重试，但此修改尚未再次在推进中的战斗验证。

## 数据与实现

`collector.py` 只读游戏进程，复用固定版本的类定位与内存传输工具。模拟器内的小型服务由随附 C 源码编译，以 `O_RDONLY` 打开游戏内存；不修改游戏数值或游戏代码，不注入 DLL。

传输只监听模拟器回环地址，经 ADB 转发连接；本地端口 27381，单实例占用端口 27380。关闭 HUD 只关闭该显示；删除源面板关闭关联 HUD，记录保留。关闭 GUI 在托盘可用时只隐藏主窗，HUD 和共享采集继续，可从托盘或 HUD 的“GUI”按钮恢复；托盘不可用时退回任务栏恢复入口。显式“退出应用”或托盘“退出 ArkDPS”才结束采集、销毁 HUD、移除托盘图标并释放本工具创建的 ADB 转发，退出日志记录清理核对结果。模拟器里保留 `/data/local/tmp/ark_dps/` 的小型服务文件，便于下次启动；不会替用户关闭 Root。

本地记录保存在 `runtime/`。战斗推进时记录采样；暂停时最多每 5 秒记一次。记录不上传。每次启动新建记录文件；导出不会覆盖其他记录，除非用户在保存框里明确选择同名文件。

确认结束的战局另存至 `runtime/history/`，每局一个版本化 JSON，按战局 ID 去重并保留最近 100 局；演习、失败、放弃和未知结果均可保存。摘要保留原始数值、归属与覆盖缺口，损坏和写入失败可诊断。读取接口与复核范围见[本地战绩契约](docs/snapshot-adapter.md#本地战绩ark-8)。

游戏版本变化时拒绝继续使用旧偏移，需重新适配。换局或中断时保留最后有效记录并显示状态；不会用零值掩盖读取失败。

开启事件观测后，采集器会保活已准备好的设备端端点：转发丢失时重建，模拟器重启后自动重连并尝试启动设备上已有的 `frida-server`；不会下载或替换服务端二进制。连接设置保存在 `runtime/connection.json`，可在 GUI 设置页修改；另一台设备也可仅在本次启动用命令行覆盖：

```powershell
python app.py --adb "你的 adb.exe 路径" --serial "127.0.0.1:16384"
```

测试命令（兼容本机旧 pytest）：

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
python -m pytest tests -q --assert=plain
```
