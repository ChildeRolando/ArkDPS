# Native meter

Operate surface: Windows C# / .NET 10 / WPF. The supplied offline prototype is the visual authority; the discarded Tk widget stack is an anti-reference, not a layout to preserve. The main window contains live, history and connection pages, with a global skin selector and explicit Exit. Initial size 1380×900 DIPs, minimum 560×540. First launch has one Damage/Totals/Recent DPS panel and no HUD. The compact 本局统计 heading and useful stage/status/game-time strip leave the primary space to contribution ranks and the pinned operator report.

## Composition and skins

`desktop/ArkDPS.Desktop/App.xaml` owns common WPF control templates and dynamic brush resources; `Theme` in `App.xaml.cs` owns the two palettes. Default 孤星 · LONE TRAIL follows the supplied mission-console direction: warm ivory enamel instruments, ceramic-orange controls/focus, deep blue-green plotting surfaces, and precise orbital line geometry. The orbital outlines are static decoration, never measured game trajectories. 原始界面 is the blue-gray/dark alternative. Only these two skins ship.

The dark masthead contains brand, live/history/settings navigation, skin choice and global HUD unlock. Live panels use a light instrument header and dark operator list rather than generic repeated form fields. Wide windows lay panels side by side (about 385 DIPs per column); narrower windows stack them. The inspector is a 300-DIP side rail on wide windows and moves below the panels with its own scroll area below 1000 DIPs. It presents the pinned portrait, cumulative contributions, independent engagement values, exact damage composition, coverage and sources as distinct sections, not a raw text dump. History has a searchable/filterable archive rail and an independent selected report; it never becomes the live/HUD source.

Skin changes update dynamic resources in place, without recreating windows or statistics, rewriting history, or touching HUD input flags/geometry/opacity. The same palette covers main, history, settings, tooltips, HUD and complete-ranking PNG. Persistence belongs to the existing version-3 layout owner, not a C# preferences file: see [settings and layout](docs/settings-and-layout.md).

## Typography, data and interaction

Microsoft YaHei UI for Chinese UI, Bahnschrift for aligned numerical readings. Body 13 DIPs, main heading 22, panel titles 17, data values 21. Outside gutters 24 DIPs; tightly grouped filters 6-DIP gaps. No ornamental motion; this is a continuously updating tool. Lists reuse keyed row models; hovering holds row order while values continue updating, leaving restores the Python model's exact ranking. Keyboard navigation selects/pins rows. Full values and names are available on hover. Unknown remains an em dash, never zero; waiting, paused, stale, degraded and disconnected states have text, not just color.

Offline portraits retain their gray variant for retired operators and a name-badge fallback for unknown IDs. The pin survives disappearance from the recent ranking and clears at new battle identity. Damage bar length and share always follow the selected ranking basis, independent of the rate column. PNG renders all ranked rows without list virtualization or viewport clipping; export freezes the selected record/configuration/skin before the native save dialog. JSON remains the unchanged BattleRecord contract.

V1 damage identity colors remain physical red `#e5484d`, arts blue `#3d8bfd`, elemental purple `#9b5cf6`, true white `#ffffff`. They are inherited semantics, not a claim of a colorblind-safe palette. Text legends, direct component names and exact-value reports supply a non-color reading path. Healing uses green, shields blue-gray; no hue is reassigned by rank. Thin segmented bars have surface gaps and exact-value hover content. Body/control contrast is checked against both actual palettes.

## HUD and recovery

HUD is a native, topmost, independently resizable WPF window (initial 410×430 DIPs, minimum 350×280) with a draggable header, main-window/close actions, compact list and visible status footer. Lock and 70–100% opacity controls remain beside the source panel; global unlock and tray recovery are always available from the main window. Locked input uses actual Win32 transparent/layered/no-activate styles, not only WPF hit-test suppression. Closing HUD leaves collection running; deleting the source closes its HUD. Closing the last HUD while the GUI is hidden restores the GUI. Closing the main window hides to tray, with a taskbar-minimize fallback when tray construction fails; explicit Exit waits for worker cleanup.

WPF uses a PerMonitorV2 manifest and persists physical HWND rectangles through the existing layout schema. Hidden/minimized/maximized frames do not replace the last normal GUI rectangle. Restore clamps to a reachable monitor work area. Desktop runtime/protocol/distribution and the honest offline/manual acceptance boundary live in [desktop runtime](docs/desktop-runtime.md); historical Tk screenshots do not certify this replacement UI.
