# 事件探针复用审计与修复边界

## 已确认的断点

本轮基线为 PC 2206 / `43bb3bb15ddb77fc2f348ea3f8c8892f9f450c05`，对应本机真实 MuMu ADB 修复包的源码为 `29ee4f4f`。两者从 rc.8 分叉，并非所有公共处理模块都相同。PC 缺少 MuMu 后续 `01b7de4` 的延迟观察基线处理；不能用“相对旧 PC 未改文件”证明已经复用当前 MuMu 行为。

弹药相关提交也不能笼统标为已支持：`3e5465a` 防止误认弹药效果结束，`91e47ecc` 发布仍开放的普通技能窗口并保留弹药例外，`35e2783` 提供已观察技能分量的展示。后续 `10ae803` 引入实际结算计量及其按 actor 维护的技能状态。当前两端都保留弹药未知保护；已观察值的承诺必须穿过新计量和最终面板重新验证。

2206 实机出现的三个问题有同一条可追溯链：

- 新约能天使有真实效果开始与施放完成标记，但没有实际弹药效果结束标记。公共弹药 guard 将技能分类保留为未知。
- 塔露拉三次普通扣血后触发嵌套元素爆发击杀；外层结算证明未形成，单次缺口又被生产者上报为全局不完整，其他干员随之降级。
- 42 个敌人入场血量合计 221000，已计我方实际扣血 207017.15028536413；差额 13982.849714635871 精确对应三段原始 HP 下降。不能改分母，也不能用名义伤害回填。

证据为按原始字节冻结的单局日志、包清单、逐实例 HP 轨迹及实际发布的统计快照；本机路径与摘要保存在 `runtime/native-pc/frida-development/standard-2206-terminal-audit-20261122-150510-1222b409`。这些材料不是可公开下载的仓库附件。

沿用 [桌面运行时](desktop-runtime.md)、[统计核心](statistics-core.md)、[累计适配器](snapshot-adapter.md) 和 [事件接口](event-probe-interface.md)。

- `EventProbe` 与宿主契约拥有来源选择、身份、时钟、前缀、重放、确认及资源清理。
- Python 公共统计拥有名义量、实际 HP/扣盾量及技能分类；两个计量域不能互相填数。

- 既有运行时继续拥有 Gadget、进程出生身份和连接生命周期；本轮不建立第二套启动器。

## 有界实现

1. 核对并复用实际 MuMu 公共处理基线。仅合入已确认相关的上游改动，保留必要的 PC 原生身份与在场证明，不复制重写统计公式。
2. 将两份探针中相同的战斗事件组装、技能与结算证明移动到共同源码；平台适配仅处理 IL2CPP 元数据、ABI、原生战局绑定及来源能力。扩展现有探针源码加载边界，不建立平行框架。
3. 使用已有逐击 `settlement_complete` 和归属承载局部证明缺口。来源仍可靠且事件完整交付时，不把一次未知提升为全局断流；序号、身份或无法归属的丢失仍须保留全局失败。
4. 以父子回调真实检查点补嵌套结算证据。父扣血、子扣血和过量的分配均需独立数值及身份证明；不能按名义量或最终死亡状态推算。
5. 调查通用技能生命周期。当前元数据存在 `CastSkillWithLimitTimes`、`AbilityEventCounter` 及 `BasicSkill` 效果状态/终止接口，但方法存在不等于语义已验证。只有实际观测到效果或弹药生命周期，才能接齐弹药起止。
6. 共用技能分类与未知原因的规则，保留名义和实际计量的区别。新计量不能悄悄覆盖旧展示契约，未知也不能变成完整零值。

共同源码不是新的统计权威：它解决重复生产逻辑可独立漂移的问题，只隔离平台元数据、ABI 与原生绑定。现有 Python `EventProbe` 不适合事后合成回调内事实；源码组成职责应放回其既有加载边界。

### 共同实现与来源字段修复

`event_probe_android2791.js` 与 `event_probe_native_pc.js` 只保留平台元数据、ABI、绑定和屏障适配。宿主通过 `assemble_probe_source` 按固定顺序组合适配器和 `event_probe_runtime.js`，同一次读取计算原始文件、规范化源码、组合源码及实际提交源码摘要。宿主自己的来源描述覆盖生产者同名字段；成功发送源码不等于已安装或已观察到事件。打包白名单包含三份 JS。

机械提取阶段五份完整输出与旧源逐对象相等，原始回执保存在 `runtime/event-probe-reuse-phase1`。后续局部故障修复有意改变错误质量声明，不再把这些错误输出当作不变基线。既有正常场景的完整 JSON 仍绑定提取前摘要；局部缺口、身份变化、丢序、重复与溢出分别检查业务真值。

局部化需要同一回调区间的来源指针、类、BObject UID、角色 data UID、CID、目标指针/类/UID、Modifier、类型及游戏时钟保持一致。一笔证据不足的命中必须实际输出带原因的 `settlement_complete:false`，不能漏记后发布完整零值。不能定位到稳定归属或发生全局传输故障时继续拒绝完整覆盖。共享聚合器不忽略历史错误批次的全局失败声明。

2026-11-22 的独立诊断进一步采到五组普通父结算与元素子击杀。原始字段冻结于 `tests/fixtures/event_probe_business/2206-native-callback-fields.json`，SHA-256 为 `da6122420941983fa56037c5e4039a81ea8b8ca2e14c3d53e7f0bab2ec52912f`，完整原日志 SHA-256 为 `ab11ea8013c14c1b008381861818d96f7ff47d38b4ea5a7880750bda82f7e907`。共同源现在在子回调进入时保存父原生 signed realDelta 与实际 HP，匹配子击杀的独立证书，再于父返回时复核原生结果、身份与时钟。父和子各自计一次，父未击杀的 HP 终点保留为进入子结算前的实际值。没有父原生结果或结果改变时保持未知。旧的“子击杀后父实际量为零”分支还必须证明子进入前 HP 等于父命中前 HP，避免把已发生的父扣血误判为过量。

真实弹药样本的施放返回读到 `BasicSkill.m_waitForSkillEnd` 从 false 变为 true；其首次真正结束时仍有既有 `Character.OnSkillFinish`，不需要另一套起止协议。新增字段 `skill_wait_for_end` 保留原生布尔值与 `BasicSkill.OnCastFinish` 方法来源，施放完成不充当效果结束。两套公共计量入口消费同一字段与同一转换函数；旧录制没有新证据时保留旧保护。当前仍开放、结束已确认、缺少结束、再次激活与覆盖断裂分别回归，已观察分量不能自动升级为完整值。原有弹药缺结束保护继续生效，普通技能即使携带新字段，也保留 MuMu 既有的可靠战斗边界截断规则。

状态观察还要求字面 Boolean 与 Int32，不能把数字 1 或其他真假值当原生布尔。角色 UID 沿用既有来源字段，在内部技能窗口绑定 actor；同 CID 的不同 UID 不能互相升级技能证明。被动施放状态不注册原生累计伤害来源，也不使无关的累计归属冲突。无匹配激活的合法 false 可以是内部真正结束后的通知，予以忽略；无匹配激活的 true 保留局部技能未知。明确的敌方、token、空 owner 或未证明属于我方的回调不发布补充字段，不因缺少此可选字段污染全员质量。

上述独立诊断到达原生终局 frame 6280 / sequence 1302，但其临时采集脚本的停止循环与同步 RPC 清理失败；自有进程已退出，远端 script/session 卸载没有确认。该工具失败另存 `final-audit-receipt.json`，不改写为清理成功，也不作为正式新包通过证据。下一次正式实机验证先正常重启游戏。

MuMu 迟接入补丁还覆盖正式无界面入口：等待观察者就绪时可以先保存原生累计，再从后来的真实事件基线开始。PC 平台显式禁止较弱的场景就绪回退，即使注入的采集器恰好提供同名方法，也必须通过原 VM 初始化门槛。

### 变更控制记录

本轮修改沿用既有采集与统计所有权。增加的共同 JS 文件是两个既有生产者的固定源码组合边界，不增加运行服务、启动器或统计权威。Python 统计先复用实际 MuMu 上游的迟接入补丁，再在既有事件接口中承载真实施放返回状态及其 actor 身份；`damage_settlement.py` 的伤害、护盾与过量公式保持原实现。面板仅修复未知原因与质量投影。

复核对象包括源回调证书、事件序号与 ACK、双平台入口、角色归属、旧录制、在途技能、晚接入、完整与破损终局、包内源码清单及宿主来源摘要。独立审查发现的 CLI 初始化分支、拆分后测试的错误源码入口、普通技能终局退化、非法状态字段和重复 CID 的 actor 归属均以可复现用例处理；不把来源相等替代业务正确。

交付状态分开登记：机械迁移已验证；真实原生字段已冻结；共同实现的离线回放和质量反例已验证的范围以测试及回执为准；最终已提交候选、便携包、标准桌面实机对账与用户界面确认仍需分别完成。独立诊断的卸载未知和旧版本失败不随新用例通过而消失。
