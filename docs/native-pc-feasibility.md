MuMu 的事件来源与精度见[事件采集约定](event-capture.md)和[统计核心](statistics-core.md)。Windows 的开源 ArkHelper 快照公开了逻辑帧、行累计及覆盖标记。其发布端使用进程内观测，目前机器上没有该发布端，独立只读接收器已通过合成数据验证。公开快照还缺少 ArkDPS 所需的逐笔结算契约。[ArkHelper 快照接口](https://github.com/zhengkanqin/ArkHelper/blob/v1.4.2/include/arkhelp/ipc.h)

对匹配构建的磁盘元数据与 `GameAssembly.dll` 做了只读核对。`BattleLogger.m_logs` 保留带游戏时间的手动部署、撤退和技能指令，可用于下一步核对人工操作。`charStats` 和 `skillTrigStats` 保存计数，`CharAdvancedStats.snapshots` 保存属性、天赋和技能配置，普通事件池保存回调集合。这些已定位字段缺少逐击伤害、自动技能起止和护盾实际吸收的事件记录。

## 接入边界

- 官服 PC 已接入 Python 采集层和 WPF 连接设置。读取器使用普通 Windows 只读权限 `0x410`，并以进程创建时间和战局身份约束缓存。构建不匹配时停止发布数值，权限不足时提示管理员启动。MuMu 继续使用其原有连接设置。
- 读取器在同一逻辑帧内核对累计、编队与在场集合，按宿主键与 UID 归并。原生全局计数单独保留用于对照。中途进入使用首个可靠累计作基线，近期速率只用该点后的增量。编队读不到时保留最后可靠数据。在场快照可显示谁还在场；全周期 DPS 需要可靠的在场时长，目前保持未知。
- 产品复用 `CollectionSession`、战局切换、统计、独立 HUD 和归档路径。历史与导出保留平台、构建和事件覆盖。普通权限运行新 CLI 已验证拒绝访问时发布零份样本，管理员正常入口已通过 1-7 累计和归档实测。官服 PC 侧栏依据 worker 验证的进程编号和创建时间跟随唯一合适的游戏窗口。找不到窗口或多个候选时独立显示，已确认窗口最小化时使用侧栏原有的收起和恢复机制。[桌面运行时](desktop-runtime.md) · [累计适配器](snapshot-adapter.md)
