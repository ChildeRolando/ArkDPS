# ArkDPS 官服 PC 只读适配可行性报告

评估日期 2026-11-21。目标是鹰角启动器国服 Windows x64 客户端，验收基线为 ArkDPS rc.8 的 MuMu 功能。当前证据支持实现 **Windows 原生累计采集**，MuMu 的逐事件统计仍有独立的数据源缺口。现阶段 PC 保持实验态，等实机验证通过后再进入产品接入验收。[MuMu 产品基线](v1-design.md) · [PC 实验记录](native-pc-research.md)

## 实机结论

| 检查 | 结论 | 证据边界 |
| --- | --- | --- |
| 进程访问与构建校验 | 普通未提升账户申请 `0x410` 返回 `ERROR_ACCESS_DENIED`。同一已签名客户端以管理员权限运行只读采集器后，句柄、三个构建哈希和内存模块对照均通过。 | 已排除 Codex 受限令牌和 Windows PPL 为本机必然原因。具体 DACL 规则及其他机器上的可访问性仍待验证。 |
| 逻辑时钟与累计伤害 | `7945b7c` 的 120 秒采集拿到 468 个稳定样本。帧 `0→4347`，游戏时长 `0→144.89986` 秒。7 个来源键可读，5 个出现累计增长。 | 倍速 2× 来自用户说明，关卡未记录。17 次跨帧或对象链变化被拒绝。 |
| 统计口径 | 最后一帧原生全局值为 `127719.6875`，7 个来源的分类伤害之和为 `183360.08203125`。原生全局使用 `realDelta`，来源分类使用 `abs(finalDelta)`。 | 全局值可用于独立对账。算全队占比时需要可靠归属后的逐来源和。两者差额不用于估计过量。 |
| 普通关卡逐事件来源 | 468 份有效样本的 `BattleVerboseRecorder` 指针均为空。现有普通日志只有 UI 与资源诊断。 | 静态分析显示默认路径为多人模式创建详细记录器，仍需匹配不同模式与运行时热更新。 |

原始 2× 记录和可复核摘要在 `runtime/native-pc/2026-11-21-battle/` 的 `admin-20261121-115527.jsonl` 与 `admin-20261121-115527-verified.json`。两次权限对照与用户提交的管理员输出在 `runtime/native-pc/2026-11-21-access/`。报告的可行结论限定到匹配探针三文件哈希的客户端和本次资源构建。[证据索引](native-pc-research.md)

## MuMu 功能齐平矩阵

| 能力 | Windows 现状 | 达到齐平的证据 |
| --- | --- | --- |
| 分类总伤害、近 5 秒 DPS | 分类计数和逻辑帧已读到。现有统计核心可复用近期窗口，须先完成来源归属和正常入口接入。 | 1×、2×、暂停、中途启动、退场后的同口径对账。跨帧或归属缺失时保持未知。 |
| 治疗累计、近 5 秒 HPS | 记录含全局与逐来源治疗字段。首轮全为零，尚无治疗触发样本。 | 先观察目标缺血再由指定医疗治疗。下一轮再区分满血治疗、持续回血与脱手治疗。 |
| 召唤物与离场输出、全周期速率 | Windows 版编队、来源 UID、宿主键及宿主 UID 的字段布局已静态核对。当前有召唤键出现，没有非零召唤输出和可靠在场时间证据。 | 确认宿主、召唤物并发及撤退再部署，保持累计不重复。全周期分母依赖已验证的在场区间。 |
| 敌情、首领、有效伤害、过量和减伤 | 敌人瞬时状态是可调查的读源。当前累计伤害无法区分目标、击杀、盾吸收或公式前后值。 | 每个敌人实例有稳定标识。首领输出与过量需逐次来源、目标、HP 前后、结算值和盾上下文对账。 |
| 有效护盾、接敌 DPS/HPS、技能期拆分 | 现有 Windows 只读来源未提供完整有序的逐次事件。可读的盾剩余量或技能状态只能支持进一步验证。 | 实际盾吸收量与施盾人，逐次伤害与治疗帧，技能起止及输出归属。丢失短时事件时应报告覆盖缺口。 |
| 战局生命周期、HUD、侧栏、历史和导出 | WPF 展示与统计逻辑具备复用边界。原生版目前只有独立采样器。 | 正常入口验证阶段和结算、同图重开、归档一次、平台切换、历史来源标识、无 MuMu 回归。 |

MuMu 的事件来源与精度见[事件采集约定](event-capture.md)和[统计核心](statistics-core.md)。Windows 的开源 ArkHelper 快照公开了逻辑帧、行累计及覆盖标记。其发布端使用进程内观测，目前机器上没有该发布端，独立只读接收器已通过合成数据验证。公开快照还缺少 ArkDPS 所需的逐笔结算契约。[ArkHelper 快照接口](https://github.com/zhengkanqin/ArkHelper/blob/v1.4.2/include/arkhelp/ipc.h)

对匹配构建的磁盘元数据与 `GameAssembly.dll` 做了只读核对。`BattleLogger.m_logs` 保留带游戏时间的手动部署、撤退和技能指令，可用于下一步核对人工操作。`charStats` 和 `skillTrigStats` 保存计数，`CharAdvancedStats.snapshots` 保存属性、天赋和技能配置，普通事件池保存回调集合。这些已定位字段缺少逐击伤害、自动技能起止和护盾实际吸收的事件记录。

## 实测安排

1. **CE-5 演习，治疗与生命周期。** 从关卡确认页开始录制。1× 部署一名无自疗的重装挡敌，等血条下降后部署安赛尔或闪灵 S1 覆盖重装。看到至少一次回血后暂停约 8 秒，恢复后切 2× 正常打完，看到结算后继续记录约 5 秒。其他路线按熟悉的阵容通关。验收看治疗干员的非零增量、帧与墙钟在暂停和倍速前后的变化，以及最终状态是否被捕获。
2. **召唤来源隔离。** 现有可用关卡选一张可稳定守门的演习，优先沿用已验证路线的 OF-2（可进入时）。用梅尔 S1 依次布置两只水獭，让它们先单独打出伤害，中途撤回一只后补上。对账宿主 UID、实体或统计键复用和计数增量；可在同一测试流程复核主动技能起止。等第一轮稳定后再定 PC 站位和时间点。[MuMu 既有作业](../acceptance/maa/README.md)
3. **盾吸收与过量对账。** 沿既有 OF-8 闪灵 S2 破盾方案核对实际吸收量，再用孤立的末击超出目标剩余 HP 的样本对账。验收依赖可验证的结算证据，画面和累计都保留各自覆盖边界。[盾破实测](capability-validation.md)

只有 PC 实机观测能改变矩阵里的验证状态。若普通只读来源最终只能提供累计和部分瞬时状态，PC 能实现相应统计，完整数值齐平仍取决于可支持的有序事件接口。
