伤害、敌人入场和技能事件共用有序队列。主机读到稳定水位后按序号取事件，入账成功再确认该水位，探针收到确认后才释放这一段。读取响应丢失时从已入账的水位重读，确认响应丢失时可重复确认。未确认事件积压达到上限后，继续写入会明确报采集缺口。为兼容历史回放，日志中的事件批次字段仍为 `drain`。

被减伤率由同一击的公式前伤害 `mitigation_before` 与结算来伤 `mitigation_after` 计算。探针观察 `AttackInfo.GetFinalAtk` 和 `BattleFormula.CalculateDamage`。同线程、同逻辑帧、来源与目标指针、伤害类型和公式输出值均与 `Entity.ApplyModifier` 入口吻合，且候选唯一时，锁定该次调用并消耗候选。调用结束时在同一 `Modifier` 上读取最终来伤，确认身份、类型和取消状态后附到现有伤害事件。CE-5 日志中可见一击在公式内从 1306 变成 306，进入 `ApplyModifier` 后再修正到 397.8。该口径计入增伤、穿透和后续伤害修正，取值在护盾吸收和 HP 实扣之前。整局覆盖完整时显示被减伤率。有缺口时，「已观测减伤率」显示已验证命中的加权结果及配对击数，后续断流保留此前验证的结果。无有效配对时保持未知。原始日志附带有界的匹配诊断。

歌蕾蒂娅 X 模组的位移法伤走 `DamageByDistance.Execute`。CE-5 演习中，8 次非零命中的 `CalculateDamage` 来源参数均为空，来源保留在该次位移动作的 Buff 中。原生 `GetFinalAtk` 读到的公式前值与 `Modifier.originAtk` 一致，公式返回与 `Modifier.originValue` 和结算入口值一致。探针在同一次位移动作内用这些字段确认来源和伤害，进入同一条伤害事件。一笔命中从 397.66655 结算为 198.83327，另一笔从 122.32895 经公式得到 61.16447，后续修正后结算为 79.51381。

敌人的入场、HP 变化、假死、重生和结束按同一战局内的实例 UID 归并。HP 事件携带实际结算后的 HP。假死等待重生，最终离场由 `Enemy.OnFinish` 确认。快照提供开局或中途接入时的存量和计划信息，并补齐事件缺口或缺失字段。事件覆盖完整且快照已初始化时，敌情随已提交的事件批次刷新。已入场总血量按已确认实例及其重生阶段累计，缺少 MaxHP 的实例保留原生 HP 下限。关卡预估血量、已观测回血和含回血累计可承受量分别显示。

敌情页的我方对敌扣血来自 `Entity.OnAfterOutputDamage` 的实际 HP 扣减。结算事件与敌方血池按同一实例 UID 和 EID 匹配。敌情快照确认的装置可纳入该口径，其他目标的输出继续计入各自的干员统计。目标或归属证据不足时，敌情页显示已确认下限。该值从事件基线累计。

同一实例变形时，HP 事件可带游戏原生的最大 HP。血条使用当前形态的最大 HP，已入场总血量记录该阶段观察到的最大容量。若出生当帧或下一逻辑帧，在首次掉血前从旧上限满血同步调整到较低的新上限满血，按结算后的上限开始累计。普通回复只更新当前 HP。当前 HP 超出旧的最大 HP 且缺少属性证据时，累计血量按已观察到的下限显示。

已由敌情快照确认的场景装置也可按 UID 接收实际 HP 和已验证的 `Entity.OnFinish` 终态。装置状态事件需与快照实例匹配后才进入敌情统计。

开启事件观测后，采集 worker 每 5 秒检查本机事件端点：若转发丢失会重建 `27043 → 27864`；若设备上已有的 `frida-server-17.26.1` 未运行，会尝试启动它。模拟器重启导致采集连接丢失时，worker 每 5 秒自动重新解析实例并重连，不需要手动「重新定位」。这套保活只复用设备上已存在的二进制。启动通过设备端锁串行化，并为每次新启动指定独立的 Frida 临时目录，防止其他服务进程启动时清理仍在使用的 ARM64 探针。健康检查同时确认设备端监听和主机转发可达。若 Frida 返回 `process is not using emulation`，界面保留快照并提示重启设备端 Frida 服务后重新定位。

`app.py` 的窗口、`start.cmd` 和 `--capture-seconds` 命令行模式共用 `CollectionSession`。通过进程身份和游戏版本校验后，默认向本机已验证端点 `127.0.0.1:27043` 尝试临时事件观测；`--frida-remote host:port` 可覆盖端点，`--no-events` 显式关闭。API 的默认值同样为该端点，传入 `frida_remote=None` 关闭，可供 ARK-11 设置入口使用。Frida 17.26.1 客户端、同版服务及端口转发须由调用方准备；采集器结束时卸载自己的脚本，不安装或启动服务、不使用 eternalize。

连接先校验进程与游戏版本，再准备观察器，最后定位战局。因此观察器可以在进入关卡前就绪。`Collector.connect()` 的默认行为保持同时定位；`connect(locate=False)` 允许提前挂载，之后调用 `locate_battle()`。

快照与编队暂时跨帧、`SampleUnavailable` 或 `RosterUnavailable` 会重试，保留观察器队列，不制造事件缺口。基线要求前后标记同帧同时间、序号及回调入口计数一致，并且没有在途回调。后续同样取得稳定配对，再提交有序事件和水位。真实换局/时钟回退拒绝串局；观察器丢失、来源冲突或序列缺口封存事件覆盖，正常采集入口仍可继续原生累计。未知护盾机制关闭覆盖。自然结束只有最终水位已到结束时间时才保持覆盖完整，接敌尾部按结束时间截断。

输出中的 `statistics` 是统计核心与宿主归并结果；原来的原生 `rows` 仍供现有伤害窗口使用。`event_status` 为 `unavailable`（用户关闭）、`attaching`、`ready`、`recording`、`failed`（启动失败）、`gap`（运行中断）、`finished` 或 `stopped`；`event_error`、`event_watermark` 与每行覆盖字段必须一起保留。依赖缺失、Frida 版本不符、远端不可达或挂载失败时，清理已创建的观察器，保留失败原因，继续原生伤害和治疗快照，护盾与接敌时间保持未知；运行中断只保留已观察的可靠前缀。可恢复的单事件问题（未验证护盾、护盾回调缺少上下文、非玩家来源、无法识别的伤害类型）只把对应护盾或该来源的过量标为未知，不关闭其他干员的伤害、接敌与过量覆盖；只有记录级失败（非法金额、缓冲溢出）才关闭整个事件覆盖，并在 UI/日志中显示实际错误文本。不会在当前局重挂载，下一局新建会话时按认证条件重新尝试。未经认证的游戏版本或无法确认的进程身份仍拒绝整个连接，不发布数值。新字段的显示界面由后续 GUI/HUD 工单负责。

普通命令行采集允许上述降级，`READY.json` 在连接与可选观察器启动/清理完成后写入，并包含 `event_status` 和 `event_error`。验收使用 `--require-events` 要求事件覆盖，启动失败不写 READY，运行缺口记录失败并清理退出；该选项不能与 `--no-events` 合用。`acceptance/run_event_acceptance.ps1` 已固定传入此选项，避免把快照降级误记为事件验收通过。

## 结算帧的发布与修订

事件时间线在可靠的结束水位处关闭。此后只接纳同一战斗、同一结束帧、同一游戏时间且状态为 3 的结算累计快照；晚到的原生累计归属原局，不创建新战斗，也不延长事件覆盖或参战区间。不同会话或回退的累计仍是错误。

`snapshot_revision` 标识累计快照修订。每次发布必须同时包含当前原生累计和用该累计更新的统计结果，不能把新原生值与旧面板拼成一次发布。重复的稳定结算快照不增加修订号。发生修订的来源没有可用的修订发生时间，其近期速率置为未知；未修订来源保留已有历史。事件序号、水位、结束时间和已观测事件累计保持冻结。原生累计变化不自动证明事件覆盖完整，离线验收仍须独立比较原生增量与事件和。

## ARK-25：伤害事件的过量证据

`event_probe_android2791.js` 在 `Entity.ApplyModifier` 返回时，对 `targetType=0` 的伤害事件追加目标 ID、签名 `realDelta`、目标 HP 前后、`killed`、`type`/`targetType`/`cancelReason` 以及同帧已验证护盾吸收量。`amount` 取原生 `m_value`；捕获样本（frame 697）证明它是吸收前的来伤值，因此 `shield_absorbed` 必须由统计层显式扣除，不能假定 `m_value` 已含吸收后的结果。探针只在同帧该目标的吸收可验证时给出吸收量；该目标在该帧出现无法解析的护盾/抵挡回调或非玩家护盾时传空，击杀对应过量即为未知。

证据只在 HP 差值与 `realDelta` 一致、目标 ID 可读且符号正确时序列化。若元素损伤条后的伤害回调目标指针为空，探针会用同帧同来源最近一次 `elemental_bar` 的目标指针/HP 作为候选，再走同一 HP 一致性校验；候选不匹配、过期或 HP 不可读时仍不序列化证据。任一读取失败不关闭伤害/治疗/护盾事件流，只让该次伤害缺少证据，统计层随即将对应干员的过量标为未知。来源 ID 读取失败时探针上报 `damage_unknown`（全队过量未知）与 `engagement_unknown`；无法识别伤害类型而被丢弃的事件按来源上报 `unknown_sources` 与 `engagement_unknown_sources`，使接敌分子显示未知而不是少算。`Statistics` 只在目标实际 HP 归零时计算 `amount - shield_absorbed - (-realDelta)`，并在 `overkill_coverage_complete` 中记录事件覆盖与证据完整性；旧探针或旧历史没有这些字段时过量未知，不补零。
