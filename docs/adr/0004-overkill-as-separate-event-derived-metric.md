# 过量伤害作为独立事件派生指标，保留含过量的总伤害

2026-11-10 创建，2026-11-11 返修（ARK-25）。返修依据捕获样本纠正了「`m_value` 已在结算前扣除护盾」的错误前提：吸收量必须显式扣除，否则击杀时的吸收会被误算成过量。

2026-11-10，ARK-25。用户在 [0001](0001-damage-totals-include-overkill.md) 中取消了把总伤害拆成有效伤害与溢出的要求，但要求在界面中补充过量数值，以便判断有效输出。本决定不重开 0001 的口径变更，而是另行暴露一个只读的事件派生指标。

决定：

- 总伤害仍是客户端逐干员累计，**包含过量**，不拆成有效伤害，也不因新增指标而扣减。
- 「过量伤害」独立累计：仅当一次伤害使目标实际 HP 归零时，以该次伤害的原生结算值减去已观测的护盾/抵挡吸收，再减去实际扣血。捕获样本（`shield-events-of8-hp.jsonl` frame 697）显示 `m_value` 是吸收前的来伤值：`m_value=14`、`realDelta=0`、目标 HP 未变而同帧 `BlockDamage` 吸收了 14。因此被吸收的部分必须显式扣除，不得计为过量；击杀时若吸收上下文缺失或矛盾（吸收量大于来伤、吸收加实际扣血大于来伤），该干员与全队过量保持未知。
- 过量不进入总伤害、伤害排行、柱长、占比、DPS 或接敌区间的分子/分母；界面必须同时标注总伤害含过量，不能把过量当作有效伤害。
- 事件覆盖不完整、目标未知、来源无法归属、护盾/抵挡吸收未验证或 HP/扣血证据不一致时，过量显示未知（`—`），不补零，并保留覆盖起止。中途启动只统计事件观察区间内的过量，`overkill_coverage_start` 标出起点，不补算观察前部分。旧历史记录没有该字段时按未知处理。
- 合成事件是本期验收手段；实机逐干员对账依赖事件观测恢复（ARK-21）后的击杀样本。
- 治疗过量不在本决定范围内，仍按既有「不额外拆分」口径。

影响：`Statistics` 事件模型新增可选的目标、`realDelta`、HP 前后与击杀证据；快照、`BattleRecord`、JSON 导出、PNG、WPF Inspector 与历史详情传播 `overkill_damage` / `overkill_coverage_complete` 等字段。真实采集探针会序列化这些字段，但任何一项读取失败都只让过量保持未知，不改变既有伤害、治疗和护盾数值。
