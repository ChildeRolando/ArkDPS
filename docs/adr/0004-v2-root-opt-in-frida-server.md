# V2：显式 root 选项与随包分发设备端 Frida server

2026-11-11，用户确定 V2 的产品方向：最终产品提供一个显式的「root 以获得详细统计」选项，并在用户选择该选项后使用随包分发的设备端 `frida-server`，而不是要求用户自行准备服务与端口转发。V1 保持不变：只分发 Frida 客户端，端点不可用时事件指标显式未知、不补零，核心伤害/治疗快照继续工作。

## 驱动

- **过量伤害（溢出）**：ARK-25 引入的 `overkill_damage` 是事件派生字段，需要逐次伤害的结算值、目标实际扣血和击杀上下文；累计快照无法还原。
- **伤害被减免率**：新增需求（2026-11-11），同样需要逐次伤害事件以及护盾/抵挡/免伤上下文。
- 其他事件专有指标（实际护盾吸收、接敌活跃区间）也随同受益。

## 决定

1. V2 在用户明确选择「root 以获得详细统计」后，随包提供与客户端版本匹配的设备端 server，并自动完成推送、启动、端口转发和退出清理。
2. 不静默提权、不把 root 作为默认路径；用户拒绝或设备未 root 时回退到 V1 的累计快照与显式未知行为。
3. server 按设备 ABI 与版本选择，使用固定 SHA 校验；仅监听回环地址，仅服务本机端点。
4. 明确披露安全与反作弊风险，并更新许可、第三方来源和分发文档。

## 后果

V1 的「客户端仅、失败即未知」边界继续有效，不得把本 ADR 当作 V1 已支持设备端分发的证据。V2 需要新增 ABI/版本矩阵、启动生命周期、root 授权与安全提示、杀软/反作弊提示以及对应验收；这些工作不在当前 V1 工单范围内。
