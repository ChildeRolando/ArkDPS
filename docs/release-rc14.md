# rc.14 发布说明

本版整合官服 PC 自有 Frida 采集端、MuMu 实际安装目录的 ADB 自动发现、始终管理员启动及分平台设置引导。PC 与 MuMu 只在事件探查与平台调用约定处适配，共用事件队列、统计、归档和面板口径。技能期比例在效果仍运行时持续更新；弹药技能不能用施放动画结束冒充实际效果结束。

## 启动与迁移

程序始终通过 Windows UAC 申请管理员权限，不提供普通权限开关。从尚未要求管理员权限的旧入口升级，需要一次完整包迁移：从托盘退出旧版，将新 ZIP 解压到新目录，把旧版 `collector/runtime/` 复制到新目录的 `collector/`，以后从新版 `ArkDPS.Desktop.exe` 启动。保留旧目录与备份。旧根启动器不会被应用内更新替换，单次管理员运行旧版更新不足以修复以后的普通双击启动。

PC 选择含 `Arknights.exe` 的游戏目录，开启观察者并应用设置，再正常重启游戏。先等待自动就绪再进入战斗。MuMu 运行目标实例并启用 ADB 与 Root，点击自动检测；唯一核实目标可自动回填，多开时选择实际游戏实例。标准包同时内置 PC Gadget 与 MuMu 设备端服务。

## 已知限制

- PC 需在 ArkDPS 开启后启动新的游戏进程；已经运行的游戏可能需要正常重启。游戏构建、进程身份或事件证据不能验证时拒绝对应数据。
- 尚无实际结束回调的弹药技能继续显示已观察数值与技能覆盖缺口，不按动画结束猜测。
- MuMu 6.8.8 的 Android 15 实例曾收到游戏闪退反馈，原因尚未确认；本版自动检测修复没有证明解决此问题。用户改用 Android 12 后恢复仅为单用户复测，不是全版本兼容认证。[原始反馈说明](event-capture.md#2026-11-21-用户反馈mumu-688-上的事件不可用与游戏闪退)
- 不恢复此前撤回的 MuMu 版本门槛方案，也不复用 rc.12 / rc.13 版本号。
- 旧有更新退出流程在战绩写盘失败时会拒绝切换版本，但仍可能关闭采集进程，尚未落盘的战绩不能保证恢复。看到战绩保存失败时，先恢复目录可写与磁盘空间，再更新。
