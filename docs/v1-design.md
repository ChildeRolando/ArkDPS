# ArkDPS V1 设计基线

日期：2026-11-07。本文整理用户在设计访谈中已确认的要求，未验证能力单独列出；不是功能已实现或完整发布验收通过的声明。决策过程见 [design-interview.md](design-interview.md)，领域术语见 [../GLOSSARY.md](../GLOSSARY.md)。

## 产品定位

免费、源码公开的明日方舟社区统计工具，沿用当前非商业许可与来源说明。优先帮助普通玩家在战斗中看清贡献，同时支持战后核对和分享。优先级为准确可信、连接可靠、看得清楚、深度分析。

## 连接与平台

- 首版以经过实测的 MuMu 为认证基线，提供连接配置、地址、ADB 路径和自动检测。
- 唯一明确目标自动连接；多目标展示实例供选择，不擅自重启模拟器或影响 MAA 的连接。
- 其他模拟器逐一验证后加入兼容清单；原生 PC 客户端另行验证。ADB 连通不能代替统计兼容验收。
- 新对局自动建立独立统计并归档旧局。GUI 浏览历史时不打断浏览，HUD 继续跟随当前对局。

## 统计规则

| 指标 | 确认口径 |
| --- | --- |
| 总伤害 | 客户端干员累计伤害，包含过量，不另计或扣除溢出；分物理、法术、元素、真实 |
| 过量伤害 | 独立的事件派生展示：仅当目标实际 HP 归零时，以来伤结算值减已观测的护盾/抵挡吸收、再减实际扣血；吸收不计入过量，击杀时吸收上下文缺失或矛盾为未知；事件不完整或证据不足为未知，不补零 |
| 总治疗 | 客户端治疗累计，不额外拆分过量；实际覆盖的恢复机制需验收并标注 |
| 有效护盾 | 实际吸收伤害，归属施盾干员；到期、覆盖、离场导致的消失不算；不混入减伤、闪避、次数抵挡 |
| 近期 DPS/HPS | 最近至多 5 个已观察游戏秒的对应增量除以实际窗口时长；2.3 秒窗口就除以 2.3，满 5 秒后滚动 |
| 接敌 DPS/HPS | 伤害与治疗分别触发独立活跃区间，每次事件延续 1.5 游戏秒，相交/相接合并；对应输出除以累计活跃时长 |

接敌区间只计实际经过的时间，暂停不推进，对局结束截断尾部，不预支未来时间；零分母不计算。1.5 秒是统一产品阈值，不是游戏最慢攻击间隔。中途连接的累计值只作为近期速率的起始基线，不能将全局累计除以连接后的短时长。

过量伤害不参与总伤害、排行、柱长、占比或 DPS 的计算，也不从未知或护盾吸收补零；界面必须同时标注总伤害仍含过量。旧历史记录没有过量字段时按未知处理。治疗过量不额外拆分。

召唤物伤害、治疗、护盾归属召唤干员，不重复累计。不统计敌方 DPS。撤退、死亡、重部署不清零；离场后的归属输出仍累计，召唤物与脱手技能在来源识别上分别验证。

## 面板与呈现

每个 GUI 统计面板独立配置：

1. 类别：伤害、治疗、护盾。
2. 排行：本局总量、最近 5 秒实时输出。
3. 伤害/治疗速率列：近 5 秒或接敌口径。护盾不套用接敌 DPS/HPS。

支持同时查看多个面板。速率列切换不改变排行、柱长或占比的分母。最高输出柱长为 1，其余线性缩放；不是 Softmax，也不固定所有柱长之和。

干员用头像标识。伤害条分为红色物理、蓝色法术、紫色元素、白色真实，无灰色溢出段。数值使用整数及 1/K/M 单位；排序与计算不舍入。头像悬停显示姓名、数字悬停显示完整数值，点击头像可固定分类、累计与活跃时间详情。

离场头像变灰。总量列表保留累计；实时列表无论在场与否，只要最近 5 秒输出归零就移除，有输出再出现。未取得可靠数据的条目不显示，但不把缺失写为零或删除此前可靠记录。面板条目移除不改变全队统计范围；总量占比使用全队本局累计，实时占比使用全队相同近期窗口输出。

## GUI 与 HUD

- GUI 面向副屏详细查看；HUD 面向单屏游戏与直播，可同时打开并共享采集。
- 在 GUI 面板点击“打开到 HUD”生成可拖动的紧凑展示。
- HUD 的类别、排行和速率配置与源面板同步；位置、大小、透明度独立并记忆。不同统计组合通过复制或新建 GUI 面板实现。
- HUD 锁定/解锁入口在 GUI。锁定时鼠标穿透，解锁后可拖动与交互。
- 关闭 HUD 仅关闭展示；删除 GUI 源面板连带关闭关联 HUD，不删除战绩或统计。
- 关闭 GUI 后，已打开的 HUD 继续运行，可由托盘重新打开 GUI；显式“退出 ArkDPS”才停止整个应用。
- 首次启动只创建“伤害/总量/近 5 秒 DPS”面板，不自动打开 HUD。之后恢复面板配置、布局及 HUD 开关状态。

## 中途启动

2026-11-07 用户最终决定：不将重连恢复作为独立产品需求或开发门槛。目标场景是玩家先开一局游戏，再启动 ArkDPS。连接后读取客户端已有的本局伤害、治疗累计及可靠归属，作为总量列表和后续增量的基线，不重复相加。

DPS/HPS 从开始可靠采集时立即起算，无需等待完整 5 秒。近期速率使用采集后的增量和实际观察时长，满 5 秒后滚动；零时长不相除。接敌速率的分子、活跃区间也都从采集开始计算，不以开局累计除以部分观察时间。启动前的事件、近期分布与接敌区间不回补。

中途启动无法补读此前的有效护盾累计，接受为已知限制，记入 [开发备忘](development-notes.md)。启动后继续采集护盾实际吸收量，记录其覆盖起点；不以剩余盾量推算历史吸收，也不把未观察部分记为零。设备端常驻观察器及其断连恢复机制不是 V1 前置需求。

## 历史与分享

本地保存最近 100 局，包含演习、失败、中途退出与结局未知，超额淘汰最旧局。展示关卡、时间、时长、结果、演习标识及全体干员统计。支持统计截图和数据导出，保留口径与完整性信息。多局曲线叠加、技能区间对比和复杂回放不纳入首版。

关卡展示使用随包的 `stage_names.json`（构建期由固定关卡表生成）把原生 `levelId` 翻译为玩家可读名称：主线显示 `1-7`，活动显示 `OF-8 名称`，肉鸽显示节点名称；未知关卡显示可读短码，原始 `stage_id` 始终保留在历史与导出中。实时页、历史列表/摘要/搜索、PNG、Inspector 与导出共用同一解析层；关卡表缺失或版本不一致会显式提示，不静默显示内部路径。

## 底层可行性验收与产品开发验收

按上述最新范围，底层 Demo 的数据可行性验收通过，可以进入正式产品开发。证据覆盖 MuMu / Android 2.7.91 下的直接伤害、游戏时钟、累计读取、实时伤害/治疗事件、已测数值盾吸收，以及梅尔/赫默/凯瑟琳的召唤归属。原始 Demo 证据见 [../VALIDATION.json](../VALIDATION.json)，扩展实测见 [recovery-validation.md](recovery-validation.md)。这不是完整产品发布验收，也不声称所有干员和特殊机制都已验证。

| 产品开发验收项 | 所需证据 | 已有基础与覆盖边界 |
| --- | --- | --- |
| 治疗累计 | 缺血、满血、持续恢复等隔离对账，明确字段语义 | 闪灵 17 次治疗事件与含过量累计对账通过；持续恢复等未验收 |
| 有效护盾 | 将已验证事件采集接入产品，扩展特殊机制覆盖 | 闪灵 S2、凯瑟琳装置吸收及部分盾破、来源区分通过；不要求启动前累计补回，任意叠盾/替换仍不能泛化 |
| 召唤物与离场效果 | 将归属合并接入产品，保持累计不重复 | 水獭并发与重新部署实际输出、赫默无人机治疗、凯瑟琳装置护盾及实体清理后的归属通过；其他体系和脱手技能逐步验证 |
| 接敌事件时间 | 明确事件或采样时间精度、阈值边界与误差 | 实时原生事件逻辑帧已捕获；接敌指标与阈值边界尚未实现验收 |
| 中途启动 | 已有伤害/治疗累计正常显示，速率只计算采集后输出 | 累计读取及归属有实测依据；产品中验证首个非零时长窗口即提供速率，护盾仅含采集后数据 |
| 自动换局与多视图 | 换局不串数据，历史浏览不被打断，布局恢复 | 当前只有采集与识别原型，无正式多面板/HUD 实现 |

来源核查保留在 [reconnect-research.md](reconnect-research.md)，其中先前“完整累计恢复”的产品要求由本次决定取代。部分字段缺失、部分干员未知时的百分比展示在产品实现中收敛，不重新引入整局历史恢复需求。

上述新增实测及边界见 [capability-validation.md](capability-validation.md)。研究事件探针未接入产品，实时可记录不等于首次连接前的历史可恢复。

视觉排版、排序动画、窗口在显示器移除后的恢复等执行细节后续通过原型评审收敛；它们不能改变本文已确认的统计口径。当前整理不包含正式产品实现或新增能力发布承诺。
