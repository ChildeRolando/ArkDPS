# rc.47 发布范围与验证边界

本版包含 PC ArkPie 采集重构，以及共享事件处理、普通关卡开局前缀和生命周期显示修复。
Frida、ArkPie 与 Android 继续使用同一业务处理与统计所有者；各平台取证和运输能力分别验证。
Windows 标准包保留现有支持的 PC/模拟器后端，不新增未经验证的游戏版本或设备支持。

## 主要变化

- ArkPie 游戏回调不再等待 QuickJS 消费者。原生层复制必要现场事实后进入有界队列，
  后台依次处理、闭合、发布、交付和 ACK。队列满、坏证据与迟到数据不默认为成功。
- 普通 Buff、伤害、护盾及公式分别按实际消费拆合同。发布、冷取证、终局、父子结算与
  独立时钟证据保留；没有通过降低采样比例、延迟解引用现场指针或放宽校验减少工作量。
- 轻量敌情不再逐笔生产普通回血流水，精确敌方累计回血及含回血可承受量显示为不可用，
  不填零。当前 HP/剩余曲线、出生/重生/离场/MaxHP 与结算内 HP 证据仍保留；我方治疗不变。
- 事件保留和 ACK 采用同一规范存储；研究型叶子压缩和全量回血生产状态不进入产品装配。
- 普通 PC 冷树通过验证后发布后续采集图，不能用新图认证旧记录。已有真实零帧边界和
  连续未 ACK 前缀时补收初始事件，不伪造零累计、空编队或未观测到的出生。
- Unit 回调目标不同于父 Modifier 时，保留现场目标描述与未核实名义值，禁止借读子对象
  作为父级结算证明。后续独立正常命中继续处理；不会把冲突命中洗成可信。
- 详情页使用已认证的生命周期在场分母；独立终局源水位可闭合战斗结束时仍在场的本体。
  普通断连、quiet successor 和缺证结束不能补造完整覆盖。

## 已运行的候选验证

发布准备基于整合提交 `d18fee509f3d662aa884ddc0d902b6d8d9819e69`，包含原始
`d14fdd110ca83b45c168374bc6acfdc5c0d0803b`。正式附件从合并后 main 的精确 CI 提交构建；
包内 `metadata/release.json` 记录实际 head、版本与逐文件摘要。

- 合并后 Python 回归6554通过、29跳过；专项297通过；桌面无输入测试验证普通/参考详情
  采用 canonical 10秒与50%，未操作游戏或本机窗口。
- 自有进程真实 DLL 五项门禁覆盖原生钩子到共享处理、发布、read/ACK、必需字段缺失、
  错目标后恢复及提前 ACK 拒绝。普通关卡真实 cold→后续图→嵌套普通40/元素60通过；
  同输入合并前反例失败于图未交接。raw ticket 0不等于游戏第0帧实机验收。
- 同一固定自有内存上核对全部伤害/公式进入、退出、父检查点、冷取证和发布字段。
  677c420 的三次干净合成试验中生产端耗时约减少52%，完整链路吞吐约增加3.7%；
  这些数值只代表该冻结输入与版本，不是当前游戏 FPS 的改进倍率。

完整字段账与版本绑定见[采集需求与字段裁剪](native-capture-demand.md)，普通关卡修复见
[H7-4根因记录](h7-4-root-fixes.md)。失败试验保留，不改写旧战绩补造缺失证据。

## 未通过或尚未完成的验证

高压混合试验仍出现持续积压：冻结候选的约6.4万条事实/秒输入最终可以排空，但稳态与
追平时间目标未通过；更早试验出现过真实 queue_full。队列容量、拒收与 ACK 规则未放宽。
此问题可能继续表现为数据过期或更新延迟。本版不宣称已根治所有掉帧和未核实命中。

自有进程与离线测试不覆盖真实游戏 IL2CPP 发现、全部游戏方法 ABI、同级实机 FPS 和
渲染/调度归因。组件性能及卫戍交接的实机验收标记继续保留实际未验证状态。

## 更新

使用完整标准 ZIP 或应用内更新。手动换目录时保留原 `collector/runtime/` 的设置、战绩和
日志。切换已运行的原生采集版本需退出 ArkDPS 和游戏，先启动新版 ArkDPS，再启动游戏。
本版仍是 RC 预发行版。
