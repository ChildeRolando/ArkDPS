# 设置、托盘与窗口配置恢复

当前入口为 `desktop/ArkDPS.Desktop` 与 `desktop_bridge.py`；配置仍由 `layout_store.py` 和 `connection.py` 独占。WPF 生命周期、物理矩形恢复、stdio 协议、运行时分发及新候选验收见 [桌面运行时](desktop-runtime.md)。本页的 v3 布局格式和迁移规则继续适用；战斗数值、历史与实时状态不进入布局。

## 布局文件与版本

`LayoutStore` 默认读写 `runtime/layout.json`（不提交），原子替换写入。

```json
{
  "version": 3,
  "theme": "lone-trail",
  "event_observation": true,
  "gui": {"x": 60, "y": 70, "width": 1000, "height": 760},
  "panels": [
    {"panel_id": "default", "category": "damage", "ranking": "total",
     "rate_basis": "recent_5s", "title": null}
  ],
  "huds": [
    {"panel_id": "default", "x": 120, "y": 140, "width": 410, "height": 360,
     "opacity": 0.75, "locked": true}
  ]
}
```

- 版本 3 增加全局 `theme`：`lone-trail`（默认孤星）或 `original`（原始界面）。未知皮肤值回退孤星并显示诊断，不丢弃有效面板或 HUD。
- 可选的 `hud_styles` 按源面板 ID 保存字体大小、窗口及列宽、行高、头像大小和间距。尺寸使用设备无关像素。关闭 HUD 后样式继续保留，重置或删除源面板时移除对应样式。旧布局使用默认样式。
- 版本 1 是早期仅含 `panels` 的文档（无 GUI/HUD、事件观测默认开启）；版本 2 保留 GUI/HUD 与事件观测偏好。两者读取时迁移为版本 3，缺省皮肤为孤星，下次保存原子写回版本 3。
- 无 `version` 但含 `panels` 的文档按版本 1 接受。未知或更高版本不静默覆盖：原文件移动为 `layout.json.corrupt-<时间戳>`，本次使用默认布局并显示诊断。
- 无法解析的 JSON、空面板列表或没有可用面板同样视为损坏：备份、诊断、默认布局。单个无效/重复面板或 HUD 条目会跳过并累计警告；HUD 必须引用仍存在的面板。
- 备份移动失败时仍可使用默认布局，但明确提示“原文件备份失败”，并禁止该 `LayoutStore` 后续保存，避免锁定稍后解除后覆盖未备份原件；用户先备份原文件、解除锁定并重启，再恢复正常保存。
- 首次 GUI 默认尺寸也按当前工作区夹取，避免小屏幕下操作区落到屏外。
- 首次启动只创建“伤害 / 总伤 / DPS”面板，且不打开 HUD。
- 透明度限制在 0.7–1.0；坐标绝对值上限 100000，尺寸上限 20000；`bool` 不作为坐标。

## Tk 历史实现与验收（已封存，不作为 WPF 候选证据）

以下保留 ARK-10/11/12/19 原实现的追溯记录。Tk 面板、`App`、`TrayIcon` 及对应验收脚本已于 ARK-27 封存到 `archive/legacy-tk`，不再支持、不得运行，其物理显示器/托盘/游戏人工验收不能继承给 WPF（[ADR 0005](adr/0005-seal-legacy-tk.md)）。当前 WPF 行为以本页上面的 v3 配置契约和[桌面运行时](desktop-runtime.md)为准。

### 可达位置恢复

保存的是绝对虚拟桌面坐标（可为负）。恢复时 `clamp_geometry()` 选择与保存矩形重叠最大（无重叠时最近）的显示器工作区：

- 完全可见的窗口保持原位置。
- 显示器移除、分辨率或 DPI 改变导致窗口不再放得下时，宽高缩到工作区大小，位置推回工作区内；HUD 不小于当前字体缩放下的最小尺寸，GUI 不小于 `root.minsize()`。
- 无法读取显示器列表时保持保存值，不阻塞启动。
- 生产 GUI 入口（含重复启动提示窗）在创建任何 Tk 窗口前检查 DPI awareness；无法建立有效 awareness 时明确退出，不在虚拟化坐标下继续恢复。命令行采集不受此 GUI 门禁影响。

GUI 位置在窗口正常状态时由 `<Configure>` 记录；隐藏/最小化期间不覆盖最后有效值。HUD 在拖动、缩放、透明度和锁定变化后通知应用保存，写盘有 600 ms 防抖。

### 托盘与关闭/退出

- 托盘使用 Win32 `Shell_NotifyIcon`，仅标准库 `ctypes`，图标为 `assets/arkdps.ico`；菜单为“打开主窗口 / 退出 ArkDPS”。双击图标恢复 GUI。
- 托盘可用时，关闭 GUI 只 `withdraw` 主窗；已打开的 HUD 和共享采集会话继续运行，随后保存布局。托盘回调或双击恢复主窗。
- 托盘不可用（无桌面 shell、创建失败或 Explorer 重启后重新注册失败）时记录诊断，关闭 GUI 一律最小化到任务栏，不因 HUD 数量改变恢复入口。运行中丢失托盘时，通过应用事件队列在 Tk 主线程恢复已隐藏的 GUI；关闭操作检查实时 `available`，不以持有托盘对象推断图标存在。
- 只有显式“退出应用”或托盘“退出 ArkDPS”才停止应用：保存布局、停止采集线程、销毁 HUD、删除托盘图标、释放本工具创建的 ADB 转发。退出时 `verify_shutdown()` 核对采集会话关闭结果、观察器 script/session 释放结果与 `ForwardRegistry.owned` 为空，结果写入 `runtime/app-*.log` 与 `App.shutdown_report`。观察器卸载或 detach 失败仍继续尝试其余资源清理，并保留失败句柄供重试；`CollectionSession.cleanup_errors` 按资源保留清理异常（包括降级到快照前退休的观察器），关闭全部成功且无既有清理错误后才置 `closed=True`。任何清理异常都会进入报告 `issues` 并令 `ok=false`；后续重试成功不抹去本次会话发生过的清理失败，不再凭空句柄或预先置位的关闭标记推断成功。
- 托盘启动等待超时会设置取消信号；原生线程在创建窗口与添加图标之后检查取消，不会晚到后留下无人管理的消息循环。`TrayIcon.stop()` 仅在线程确认终止时返回 `True` 并清空句柄；等待超时返回 `False`，App 保留托盘所有权，显式退出继续有界等待，未确认停止前不销毁 Tk。
- 设置重连或连接失败后的会话清理异常不再退出唯一采集线程：保留旧会话且暂停其输入，结束扫描状态并显示可重试诊断；用户重新定位或再次应用设置后先重试清理，成功后才新建连接，避免资源重叠。已成功释放但存在历史清理错误的旧会话保留在退出核对中，不被新会话覆盖。
- 启动或换局时观察器停止失败，实例转入 `CollectionSession._pending_observers`，只退出实时事件输入，不退出资源所有权。`close()` 对所有待释放实例和当前观察器分别重试，某一实例失败或中断不妨碍其他观察器及 collector 的释放；仅成功停止的退休实例移出待释放列表。
- 关闭 HUD 仅关闭该显示；删除源面板前关闭其 HUD，再保存布局。关闭最后一个 HUD 且 GUI 处于隐藏/最小化时恢复 GUI，避免只剩托盘图标。

每个采集样本只经 `render_panels(reset=...)` 刷新一次 HUD，并将换局 reset 传给 HUD，保留换局清除固定选择的行为。

托盘图标消息循环位于独立线程；菜单命令通过应用事件队列回到 Tk 主线程，绝不从托盘线程直接操作 Tk。

### 连接设置与多实例

设置页（主窗“设置”）编辑 `ConnectionConfig` 并写入 `runtime/connection.json`（格式见 [连接配置](connection.md)）：

- 自动检测开启时按 `adb_path` 扫描实例；唯一已认证实例自动连接。多实例时列出候选；已保存地址若仍在候选中则优先使用，否则要求玩家选择。
- 自动检测关闭时必须填写实例地址，作为手动目标；缺失时拒绝应用并提示。
- “检测实例”在后台线程执行只读 adb 检测，结果回到主线程；失败只显示诊断，不关闭设置窗。
- 命令行 `--adb` / `--serial` 只覆盖本次启动的有效连接 `App.connection_config`，不改长期偏好 `App.connection_preference`。设置页始终从长期偏好初始化 ADB 路径、实例地址和自动检测开关，并在本次存在覆盖时提示：应用后使用表单值。因此未修改连接字段（例如仅切换事件观测）不会将 CLI 值提升为长期配置；显式编辑的字段才改变下次启动的配置。再次应用或重开设置页也不重新套用旧的 CLI 覆盖。
- 命令行采集模式仍使用默认 adb 与 `127.0.0.1:16384`，不读取、迁移或备份 GUI 布局文件；损坏或未来版本的布局留给下次 GUI 启动显示诊断并回退默认布局。

### 事件观测开关

设置中的开关默认开启（认证环境），写入布局文件的 `event_observation`；`--no-events` 仍可单次关闭，`--frida-remote` 可覆盖端点。布局的自动保存与退出保存只写回该长期偏好，不会把本次启动的命令行覆盖结果写回；只有设置页的“应用并重新连接”会更新它。设置页用 `event_setting_status()` 区分：

| 状态 | 显示 |
| --- | --- |
| `disabled` | 已关闭 · 仅使用伤害/治疗快照；护盾与接敌区间未知，不记零 |
| `dependency_missing` | Frida 依赖或端点不可用 · 快照降级继续 |
| `interrupted` | 事件中断/结束 · 保留已覆盖区间，快照继续 |
| `unsupported_version` | 游戏版本不支持/未安装 · 拒绝发布任何实时数值 |
| `active` | 事件观测运行中 · 护盾与接敌区间只含已观察区间 |

Frida 端点是本次运行的连接参数，不进入布局或连接配置。`App.event_endpoint` 保留启动时的自定义 `--frida-remote`（未指定时使用默认端点），`App.frida_remote` 仅在观测启用时使用该端点。应用任何设置，以及关闭后重新开启事件观测，都不将自定义端点替换为默认值。

未覆盖区间始终显示为未知；快照降级提示只说明伤害/治疗累计继续，不把事件指标写成零。

### 验证

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
python -m pytest tests/test_layout_store.py tests/test_desktop_bridge.py tests/test_wpf_contract.py -q --assert=plain
python -m pytest tests -q --assert=plain
python acceptance/verify_wpf.py --output runtime/wpf-settings-layout
```

封存的 `acceptance/verify_settings.py` 曾用合成统计和合成多实例载荷驱动真实 Tk 窗口与系统托盘，再做一次**子进程重启**核对面板、HUD 位置/尺寸/透明度/锁定和 GUI 几何（该脚本已不可运行）；移除显示器与 DPI 变化以注入工作区模拟，另外真实创建并释放一个本工具自己的 adb 转发。主阶段与重启阶段均在创建任何 Tk 窗口前设置并检查 DPI awareness；设置失败不继续几何验收。

重启前先删除旧的 `restore-receipt.json`，要求子进程退出码为 0，并验证新回执的 `phase=restore`、`status=PASS`、当前候选 `head` 与本次父进程生成的 `run_id`。丢失/损坏回执、超时、非零退出或候选/运行身份不符均明确失败，复用输出目录也不能借用旧 PASS。回执的 `code_sha256` 同时记录采集会话、事件观察器和验收脚本本身。

已归档的 `archive/legacy-tk/tests/test_settings_lifecycle_regressions.py` 曾以故障注入固定生产 DPI 门禁、默认几何夹取、HUD 单次渲染、Explorer 重新注册失败、托盘启动/停止超时后的所有权，以及设置重连和连接失败后的清理重试。11 个用例在原候选 `6abe80c6db69a2126e3363cc15ca952c4863a12b` 上实际失败，修复后通过。真实 Tk 用例同时覆盖有/无 HUD 时的托盘丢失恢复与任务栏回退。恢复验收将事件偏好相等性纳入必需断言；注入相反偏好的两个用例在旧验收脚本上错误得到 PASS、断言失败，新脚本明确拒绝。

原 `tests/test_settings_review_regressions.py`（其余用例随 Tk 封存；句柄重试与备份失败两条已迁入 `tests/test_shutdown_failures.py`、`tests/test_layout_store.py`）曾以故障注入固定启动/换局清理失败后的句柄重试、多个退休实例释放失败时的隔离、备份失败后原文件保护，以及重启回执新鲜度和 DPI 初始化顺序。前六个用例在候选 `4b30e9e0e47c987c45673755145aa0e54ebbb2e1` 上实际失败（两条句柄丢失、两条备份诊断缺失、两条旧 PASS 被接纳），修复后通过；`tests/test_collection_session.py` 和 `tests/test_shutdown_failures.py` 同时要求退出再次尝试并传播持续的清理失败。
