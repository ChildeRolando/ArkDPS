# ArkDPS 产品设计访谈

状态：第一轮，尚未形成完整共识。记录用户已明确的意图与待决问题，不作为已批准的实现规格。2026-11-07。

## 用户已经明确的目标

- 项目名 ArkDPS，目标是社区第一 DPS checker；“第一”的具体验收标准尚待定义。
- 独立置顶小窗。面向模拟器或原生 PC 客户端；尽量支持多种模拟器，技术困难时首版可以收窄。
- 设置中的连接配置、连接地址、ADB 路径，以及自动检测连接。
- 列表用干员头像标识；条形使用红色物理、蓝色法术、紫色元素、白色真实、灰色溢出。
- 全部干员条长之和固定；用户暂称 Softmax，数学映射待确认。
- 数字为有效总伤、最近 5 秒有效 DPS、有效伤害占比；数字均排除溢出；单位 1/K/M，精度与边界进位规则待确认。

## 已知事实与当前差距

- 现有 Demo 在 MuMu 12 / Android 2.7.91 验证含过量伤害的干员累计读取；不能据此宣称准确获得每位干员的有效伤害与溢出分类。见 ../VALIDATION.json。
- 单人隔离命中能对账敌人 HP，不代表多人同帧命中能够归因。全局与干员总和差值不能按占比摊分为真实溢出。
- 普罗旺斯与天火是测试地图的固定 NPC；其死亡前的本局伤害不是串局。
- Softmax 指数变换会改变比例；按总和归一化也能满足总长度固定，并保持数值比例。
- 灰色溢出加入固定总长柱条后，柱条比例与排除溢出的伤害占比具有不同分母，必须明确说明或更改视觉方案。
- 原型继承的许可是 Tim23333 Non-Commercial Software License v1.0，不是 MIT。公开仓库的可见性与软件许可是不同决策，不能自动重新授权。

## 设计树与第一轮问题

1. 产品成功标准与主要使用场景 → 比较、历史记录、分享、验收优先级。
2. 有效伤害精度是否是公开版本发布门槛 → 采集路线、未知状态、可支持的技能与机制。
3. 条长映射与灰色溢出的阅读语义 → 分母、比例、极端值、零伤害与颜色可访问性。
4. 平台发布策略 → 连接检测、实例选择、版本兼容和自动恢复。
5. 社区分发与商业意图 → 公开时机、许可路线、贡献及发布方式。

本轮待确认建议：以对局中快速看清贡献为主，战后能核对；有效伤害与溢出准确归属是正式发布门槛；线性归一化保留比例；优先认证 MuMu 并独立评估其他平台；免费社区项目，公开前整理分发内容。以上均为建议，并未替用户选择。

## 连接事实调研

- [MAA 官方连接设置](https://docs.maa.plus/zh-cn/manual/connection.html)支持在单个模拟器运行时自动填写路径、地址和配置；多开与动态端口需要实例识别。建议唯一明确候选自动连接，多候选由用户选择；这项交互建议尚待确认。
- [明日方舟官方 PC 开放公告](https://ak.hypergryph.com/news/7388)确认原版游戏存在 Windows 原生客户端；原生 PC 是独立连接模式，不使用 ADB。
- [上游读取前提](https://github.com/Tim23333/Arknights_timer/blob/5734c30bf54780056ff758505380322c0cf519fe/tools/enemy_health/README.md)明确 MuMu + adb root；多品牌设备发现不等于统计采集兼容。
- [上游版本资料](https://github.com/Tim23333/Arknights_timer/blob/5734c30bf54780056ff758505380322c0cf519fe/game_data/README.md)将 PC 偏移作为结构对照；存在偏移文件不能作为 ArkDPS 已支持 PC 采集的证据。
- 首版平台取舍是发布策略问题，目前没有证据判定其他模拟器都存在不可克服的技术困难。
