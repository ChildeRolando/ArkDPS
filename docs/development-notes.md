## 2026-11-10：ARK-19 双皮肤与交互候选

基于 ARK-11 已合入的 `58f564e`，复用既有实时、HUD、历史与设置/托盘实现。原型新增的其他活动皮肤不扩大本票范围；原生仅提供默认孤星与原始界面。主题是展示偏好，布局升级为版本 3 并迁移版本 1/2；统计、采集与历史 JSON 契约不变。视觉权威见根目录 DESIGN.md，持久化与交互不变量分别见设置/布局和面板契约。

主题持久化新增用例在 `58f564e` 的原始 `layout_store.py` 上实际失败（`Layout` 不接受 theme），实现后通过。主题切换保留 pinned owner、hover 顺序、canvas 行身份、历史副本以及 HUD 窗口身份/位置/大小/透明度/锁定。新增历史筛选不能使当前查看的冻结副本被换局、过滤或归档淘汰替换。

本票新增验收使用合成数据和私有下层测试窗口：双主题 Windows 原生鼠标输入、托盘原生回调与独立进程重启可复核；实际 MuMu 游戏收点击和物理托盘双击仍需人工补证，不将离线测试冒充该证据。宿主设备由 ARK-14 串行占用，本票不连接设备、操作游戏或修改其转发/观察器。继承的 V1 红/蓝/紫/白伤害配色不满足通用色盲分类色校验，保留语义颜色契约并提供文字图例与数值分解；本票新增皮肤的文字/选择对比度由测试执行校验。

## 2026-11-09：ARK-11 设置、托盘与布局恢复

布局文件升级为版本 2，保留版本 1（仅面板）迁移路径；损坏或更高版本先备份为
`layout.json.corrupt-<时间戳>` 再使用默认布局，不以静默覆盖换取启动成功。
恢复坐标按工作区夹取，覆盖显示器移除与 DPI 变化；恢复窗口配置不代表恢复未观测事件。
托盘可用时关闭 GUI 只隐藏主窗，只有显式退出停止采集；退出时核对会话、观察器与
本工具 ADB 转发均已释放。事件观测开关默认开启，设置页区分关闭、依赖/端点缺失、
中断与不支持版本，降级只承诺伤害/治疗快照继续。
显示器移除与 Windows DPI 变化的物理可达性已于 2026-11-09 获人工确认（候选
`d958299`）；真实游戏退出清理亦已有同日人工补证（候选 `dd35a80`）。二者是既有候选的
证据，不表示后续返修重新执行过实机操作；物理托盘右键菜单点击仍未执行。精确提交、
证据评论与实现契约见[设置、托盘与窗口配置恢复](settings-and-layout.md)。

2026-11-10 返修进一步固定：启动/换局清理失败的观察器保留在会话待释放列表，退出逐一重试；
损坏/未来版本布局若未能备份则禁止保存，不因后续锁定解除而覆盖原件；重启验收同时核对
子进程退出码、本次运行 ID 和候选 SHA，不接纳旧回执。两阶段均先设置并检查 DPI awareness，
再创建窗口。相应回归及原缺陷上的实际失败记录均登记在上述权威页面。

## 2026-11-09：ARK-13 机制覆盖验收范围

产品补验发现山 S2 的 HP 持续恢复没有进入原生治疗累计；原生 HPS 仅表示已测原生治疗计数口径，不能作为全部 HP 恢复。普通治疗的过量、盾自然到期不计吸收、战中启动不回填历史盾吸收、NPC 输出和离场累计保留已取得限定范围的产品证据，详见 [覆盖报告](capability-validation.md)。赫默自动借助战已成功，召唤治疗和脱手满血治疗已补验，等待独立评审；ARK-13 不再因支援缺失或已取消的护盾实验阻塞。

用户进一步取消护盾覆盖替换与多盾吸收顺序实验，二者不再卡交付。有效护盾限定已验证来源和已观察区间的实际吸收；闪灵 S2、凯瑟琳装置通过当前 Buff 直接归属，其他机制未知或覆盖不完整。没有可靠吸收归属时才调查独立的护盾施加量口径，不与实际吸收混算；现有路径可直接归属，本轮无需新增施加量实验。

赫默探机补验发现宿主在场状态错误地包含存活召唤物。现改为只以宿主本体的 live UID 判断在场；离场后的探机治疗仍完整归入赫默，不能因此把赫默显示为重新在场。该缺陷的定向回归在旧实现失败，修复后验证治疗继续归并且离场头像保持灰色。

事件中断后的下一局自动重试原先缺失，已在确认的新局边界补入一次重试，旧局可靠事件前缀不变，新局重新建水位；失败仍可发布原生累计，不在同局反复挂载。回归条件与实机覆盖分别记录于 [事件采集](event-capture.md) 和覆盖报告，不以离线回放冒充设备验收。

V1 统一验收离场后的累计与归属。死亡和撤退属于离场，离场原因不影响该统计口径。沿用 M8-6 已有的在场到离场对账。

## 2026-11-09：ARK-9 实时 GUI 候选

独立评审的两项 P2 已修复：空态沿用全队完整性，未归属来源存在时不再声称可靠零；
提示框改用指针显示器工作区并约束四边，底部不足向上展开。`tests/test_gui.py` 固化
伤害/治疗未知来源与三种显示器坐标边界；新增 5 项在原实现失败，修复后通过。
验收脚本增加实际下方面板悬停、工作区四边与提示框截图，并以 `--native-scale`
将真实 Windows 缩放与 Tk 字体缩放区分。当前两屏 96 DPI，125% 原生缩放预检明确失败；
验收③的 Windows 实际 125%/150% 宽窄窗口证据仍缺，需宿主机补验，不能宣称本票全部验收完成。

默认面板现消费统一统计结果，多面板独立配置且共享结果；提供离线头像、灰像、悬停、固定详情和 HUD 入口。
测试固化短窗口、不完整占比、单/多面板对账、隐藏行的详情、换局清除、悬停排序与宽窄重排。
开发中发现窄窗重排必须清除旧列的 grid uniform 分组，否则旧空列仍分走宽度；该回归已由 GUI 集成测试约束。

本机显示器为左侧 1080×1920（负 X 坐标）与主屏 1920×1080，均 96 DPI。
GUI 验收脚本在真实 Tk 窗口遍历显示器；100/125/150/200% 使用 Tk 字体缩放，未修改用户的 Windows 设置。
原生桌面截图接口在执行器返回黑图，已改为对本窗口父句柄调用 PrintWindow，并检查非黑图；
不使用对 Tk 子句柄的黑图作为证据。混合原生 DPI 和运行中改变 Windows 缩放仍需宿主机人工覆盖，
本票的字体缩放矩阵不能宣称覆盖这些情况。精确候选、命令结果及截图收据随 PR / 工单交审。

## 2026-11-07：接受中途启动的护盾统计限制

用户决定取消重连恢复这一独立需求。V1 需要支持的场景是先开游戏对局，再启动 ArkDPS：读取本局已有伤害、治疗累计，DPS/HPS 从可靠采集开始立即计时。已观察不足 5 秒时用实际观察时长，零时长不相除；接敌速率也只使用采集后的事件及对应活跃时间。

有效护盾无法从当前游戏快照补回启动前的历史吸收量。该限制已接受，**不阻塞正式开发，不要求为此部署常驻设备观察器或继续调查原生历史恢复**。启动后按已经验证的实时事件路径累计有效吸收，归并到施盾干员/召唤宿主。

实现时保留采集起点与指标覆盖范围，区分“完整本局伤害/治疗累计”和“采集后护盾累计”。未采集时段不是零，剩余盾量不是历史吸收量；历史保存与导出沿用这些覆盖信息。具体呈现沿用产品的可靠数据规则，不引入新的确认流程。

## 阶段结论

按这次收敛后的范围，底层 Demo 数据可行性验收通过，进入正式产品开发。实测证据见 [能力报告](capability-validation.md)及[补充实验](recovery-validation.md)。研究结论覆盖已测版本和机制；统计引擎集成、接敌窗口、GUI/HUD、连接设置、100 局历史、生命周期与兼容性是正式开发中的实现和验收工作。

这次仅更新需求与阶段结论，没有改动旧原型运行逻辑，也没有修改原始实验结果或将未测机制写成通过。原始逐轮校验中的 `whole_demo_accepted: false` 表示当轮的范围，不覆盖后来的产品范围决策。
