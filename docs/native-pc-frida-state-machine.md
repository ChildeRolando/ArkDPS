# 官服 PC Frida 生命周期与恢复约束

本页约束启动组件、采集会话与界面的组合行为。运行时状态及合法转移以
`native_pc/frida_runtime.py` 的 `RuntimeState`、转移表和不变量检查为执行入口。
序列验收不得把认证固定为成功，也不得用 PID 代替进程实例。

## 所有权与状态的边界

| 所有者 | 持有的事实或资源 | 不得代替的事实 |
| --- | --- | --- |
| `CollectionWorker` | 当前请求 revision、唯一启动运行时、唯一采集会话、待完成的显式重试意图 | 启动成功不等于探针就绪或本局事件完整 |
| `NativePcFridaRuntime` | 已核验构建、监听准备时间、每个进程实例的加载尝试、租约、加载器、认证端点 | 已载入 DLL 不等于已认证；PID 相同不等于进程相同 |
| `CollectionSession` / 观察者 | 自己的脚本、会话及所有待清理观察者 | 重连成功不能补回断线期间的事件 |
| 战局生命周期 | 本局起止、不可追回的事件缺口、累计与归档 | 新连接的错误不能改写旧战绩 |
| `DesktopState` | 当前连接投影与保留的旧局视图 | 旧局的 `gap` 不能伪装成新连接失败；连接 `ready` 也不能抹掉本局 `gap` |

启动运行时跨越会话重连持续存在，因为在采样器或观察者建立之后才启动监听会错过早期加载窗口。
观察者释放后，Gadget 仍按游戏进程生命周期驻留；这是显式的生命周期约定，不视为脚本或端点清理成功的证明。

## 启动阶段

| 状态 | 可接受的后续事件 | 约束 |
| --- | --- | --- |
| `stopped` | 首次 `start` 或关闭 | 尚未开始加载 |
| `starting` | 预检完成、已有租约恢复、预检失败、取消 | 写入目标前必须有当前构建依据 |
| `waiting_for_endpoint` | 本机端口释放、取消 | 不读取、替换外部采集器凭据 |
| `waiting_for_process` | 唯一合格新实例、歧义解除、显式重试、取消 | 监听窗口由准备时刻定义，不由后续重扫或退出检测反向改写 |
| `loading` | 加载完成、目标退出、取消后清理 | 已提交的 Windows 操作由原所有者负责，不能因取消丢失路径内存或句柄 |
| `authenticating` | 认证成功、临时端点不可用、身份冲突、目标退出、取消 | 认证重试不得再载入一次 DLL |
| `ready` | 观察连接、传输失效、显式重试、目标退出、取消 | 同一份一致快照必须含租约、实例、已认证端点；不能同时已取消 |
| `process_failed` | 当前实例退出或安全地重新核验已有组件 | 不对同一出生实例再次加载 |
| `failed` | 修复条件后的显式重试或关闭 | 与可自动恢复的等待区分，错误及所有权均可见 |
| `stopping` / `cleanup_pending` | 清理完成或再次清理 | 未成功清理的资源继续有所有者，不能创建替代者 |
| `closed` | 重复关闭 | 不允许重新 `start` 或 `retry` |

外部进程和端点可以在两次观测之间改变。`ready` 表示最近一次认证的完整状态，不承诺外部对象永不退出；
真正附加及消费绑定时仍核对进程出生、路径和模块。失效反馈撤销就绪，不能沿用旧租约附加到复用后的 PID。

## Windows 加载的两个阶段

提交前，必须在同一个可取消、有期限的准备过程内确认没有既有 Gadget，并取得已就绪的 Windows loader export。
模块列表尚未初始化或正在变化时，`EnumProcessModulesEx`、`GetModuleFileNameExW` 可能失败；准备期的暂时失败可重试查询，不能直接当作已经尝试加载失败。[微软模块枚举说明](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-enumprocessmodulesex) · [模块路径查询说明](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getmodulefilenameexw)

提交后，加载线程仍在途或结果尚未核实时，只能继续等待、验证或清理原操作，不得再次提交加载。
线程结果必须跨后续模块查询失败保留；`pending_thread` 或 `pending_loader` 为假不证明从未提交，因为查询也可能发生在线程结束之后。
认证端点重试与加载提交分别计数，任何一次模块查询恢复都不能制造第二次加载。

## 探针初始化与断开归因

`BattleController` 类及静态字段可读还不足以准入探针。原绑定检查前后须读取同一构建的初始化计数、晚期初始化字节、退出字节及 Baselib 初始化锁 owner/depth；只有计数为正、晚期字节为 1、退出字节为 0、锁空闲且前后元组一致才准入。计数在初始化开头递增，晚期字节也早于全部初始化工作结束，二者均不能单独证明就绪。精确 RVA、类型和控制流字节见[离线二进制证据](../runtime/native-pc/desktop-fsm-fix-20261122-130142/il2cpp-readiness-binary-proof.json)。已知初始化等待与异常域值、读取失败分别处理；不能把访问异常一律改成等待。类枚举在读取名称前检查空指针，必需类及布局仍须全部通过，不能要求整个懒初始化缓存预先非空。

全局门槛通过也不保证每个类的字段表和方法表已展开。探针须通过 `il2cpp_class_get_fields`、`il2cpp_class_get_methods` 的零初始化迭代器触发对应元数据准备，完整有界枚举后，继续核对自身成员数量、原表地址或指针、声明类、名称、偏移和签名。字段按 32 字节记录枚举，方法按 8 字节指针槽枚举，不能混用。此路径可能写入运行时元数据缓存或分配静态存储，但不应调用 `il2cpp_runtime_class_init` 执行静态构造。精确 ABI 和代码证据见[惰性元数据证明](../runtime/native-pc/desktop-fsm-fix-20261122-132153/il2cpp-lazy-metadata-binary-proof.json)。

主动停止、错误清理或取消须先为对应的物理会话标记释放意图，回调捕获该会话的标记。主动释放或已退役会话的迟到回调不得改变新会话的状态、错误、就绪信号、待处理请求或认证世代。当前会话的真实断线仍撤销就绪，并在旧脚本和会话释放后恢复认证。探针脚本错误保留原始错误及可用堆栈，不能因随后的主动清理而改报端点故障。

## 请求、恢复与取消

1. 用户应用设置或重扫产生新 revision。自动重试沿用原 revision，旧请求不能覆盖较新的请求。
2. 显式重试意图先保存，只有旧 Session 已释放、运行时接受重试后才消费。清理失败不能丢掉意图。
3. `retry()` 调解原运行时，保留仍有效的监听窗口、加载尝试及租约；等待或加载中不得另建并行所有者。
4. 端点暂不可用自动重试认证。认证成功世代改变后，可以让失败的观察连接恢复；永久探针不兼容不能按轮询周期反复重建。
5. 运行时重新认证前先释放旧观察者持有的脚本和会话。任一 pending 观察者清理失败，都阻止替代观察者。
6. 取消与加载提交有明确先后。提交前观察到取消则不开始；已经提交的系统操作继续受追踪，且取消后不再发布新的就绪状态。
7. `wait_ready` 即使已经就绪也检查取消。就绪撤销和租约变更在同一锁内发布。
8. CLI 就绪与初始化重试共用等待预算；预算用完不再发起新重试。同步调用本身不承诺可抢占。零超时只允许一次立即检查。
9. Worker 的 Session 创建、所有权发布和连接准入与退出共用请求锁。退出先获得锁时不创建新 Session；准入先完成时，该连接归入在途操作，由退出负责取消和清理。阻塞的 `connect` 在锁外执行，避免退出无法发送取消。

## 覆盖状态与显示

重连期间可保留最后有效视图，但要标为中断。新连接尚未产出样本时，主状态保持等待或冻结并注明上次快照，不使用旧局的错误解释当前连接，也不显示正在统计。
新的实际样本到来后，显示该样本的真实覆盖；同一局已关闭的事件流仍为 `gap`，不会因为新探针 `ready` 改为完整。
历史战绩和原始缺口不作回填。

## 验证边界

- `tests/test_native_pc_frida_state_sequences.py` 使用出生绑定的假句柄、可脚本化的认证端点和独立资源账本，在每个稳定步骤核对不变量。
- `tests/test_native_pc_windows_loader.py` 是加载器直接回归入口：对实际 `WindowsGadgetLoader.load/poll` 注入 Windows API 结果，覆盖准备期 299 后恢复、提交后验证 299、在途等待和取消；与状态序列共同检查进程出生及提交次数。
- `tests/test_native_pc_battle_probe.py` 验证初始化元组、异常域值、读取失败及绑定前后的状态变化；`tests/test_native_pc_observer_initialization.py` 验证旧类绑定已经可读时仍不提前构造观察者。
- `tests/test_native_pc_frida_probe.py` 执行实际 JS 的受控夹具，覆盖字段和方法同时惰性展开；数量、迭代器、表地址、声明类或布局不一致仍失败，无关空行防护不放宽必需类检查。
- `tests/test_native_pc_observer_detach.py` 验证脚本错误后的主动清理、延迟旧回调隔离及当前会话真实断线恢复。
- `tests/test_native_pc_worker_state_sequences.py` 通过实际 Worker 请求循环覆盖自动重试、显式重试、清理失败、等待中重扫和认证恢复。
- `tests/test_observer_ownership.py`、`tests/test_shutdown_failures.py` 验证未释放资源不能被替代、失败记录不能被成功重试抹掉。
- `tests/test_native_pc_projection_states.py` 验证当前连接与旧局覆盖的分离。
- `tests/test_capture_cli.py` 验证等待预算、取消边界、永久错误及已有采集所有权。

这些是确定性的受控序列和指定并发边界，不等于穷尽 Windows 的所有调度。交付还需包内协议检查和独立的实机连接验证；
此前 CE-5 的事件对账只认证其记录的探针、构建与机制，不能充当新生命周期实现的全部证明。
